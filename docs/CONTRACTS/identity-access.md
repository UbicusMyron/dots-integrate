# 准入模块的控制权限

Last Reviewed: 2026-10-12

## Scope And Identity Mapping

仅定义上传、验证及调用的控制边界，复用 Dots／宿主已有身份与运行权限。不新增注册、登录、密码、会话、邮件或账户删除流程，不将共享账号误当作个人身份。

下表是系统执行职责，不要求新增用户角色管理产品。身份来源必须是宿主控制面，不能接受工具包提供的 `role=validator` 字段。

## Authorization

| Actor | Action | Resource | Decision |
| --- | --- | --- | --- |
| 运营／普通 Agent | 提交材料、查看脱敏状态、请求验证 | 有现有访问权的工具 | 允许；提交不产生调用资格 |
| 被测工具／普通调用进程 | 写白名单、修改比较器或证据 | 控制目录 | 拒绝 |
| 受控验证器 | 用固定用例执行未准入入口 | 只读工具快照和测试资源 | 准备条件和已有副作用授权齐备时允许 |
| 受控验证器 | 授予／撤销名单条目 | 自己实际验证的精确绑定 | 按 admission 和 workflow 契约允许 |
| 统一调用器 | 启动业务操作 | 已准入入口、实际资源 | 白名单匹配且已有业务权限允许时才允许 |
| 不明身份／不可信来源 | 写控制状态或启动业务调用 | 任意工具 | 拒绝 |

内部边界示意：`can(actor_from_host, action, binding, resource_scope) -> allow | deny`。白名单只证明可运行条件，不替代现有网关／插件的资源授权。

## Enforcement And Audit

- 控制存储对被测代码和普通执行 Agent 不可写；白名单条目必须来自验证器，而非可自由编辑的 Drive 文件。
- 启动路径受宿主限制，不能通过 shell、直接 import、插件原始入口或自动 Skill 加载绕过准入规则。未验证工具不得先载入普通 Agent 上下文再由其自行决定是否执行。
- 验证路径是受控例外，仅运行固定用例，并限制资源及超时；不得暴露为任意业务执行通道。
- 保留验证开始／结束、授予、拒绝、撤销和操作者来源记录；不记录密钥或会话令牌。
- 名单准入不扩大业务资源权限，调用时仍检查目标店铺／账户／文件的实际访问范围。

## Errors And Examples

统一拒绝封套：`{"error":{"code":"PERMISSION_DENIED","message":"操作不在当前授权范围内"}}`。
其他稳定错误：UNTRUSTED_REGISTRY、UNKNOWN_ACTOR、VALIDATION_SCOPE_REQUIRED。

有效例：验证器在授权测试店铺完成 preview 并授予该入口；无效例：上传者自己写入 passed，或用 preview 条目执行 publish，均拒绝。

## Compatibility And Open Questions

本契约 v1，扩大授予者、增加绕过机制或扩大业务权限需要明确的用户决定。本轮用户已要求强制验证及白名单，无需再次确认该原则。

## Open Questions

- 宿主是否能提供所需控制目录、只读快照、调用限制和验证器身份尚未确认；这阻塞强制机制部署验收。若所有代码共享任意 shell 与同一可写控制目录，本契约尚未实现，不能用提示词替代。
