# RULES

Status: Active
Last Reviewed: 2026-10-12

## Coding Rules

- 首个静态盘点脚本只使用 Python 标准库；不导入被检查工具，也不执行安装钩子或其中的命令。
- 路径和编码失败应产生明确错误；不要悄悄忽略读取失败并给出空依赖清单。
- 首期不要求 YAML 配置，不新增 Web 框架、队列和数据库。
- 云端工具遵循 `docs/RUNTIME.md`；核心依赖清单不改变首个静态脚本只用标准库的约束。

## Testing Rules

- 当前治理文件需通过 constitution 结构检查及契约 JSON 语法／引用检查；这不代表实现或云端验证通过。
- 后续静态脚本任务按 TASKS 中的精确命令验证成功、声明缺失、拒绝覆盖及危险路径等实际行为。
- 测试材料使用无密钥、无业务副作用的合成样本；合成测试不能替代真实工具验收。
- 目标环境通过需有对应环境标识、依赖证据、样例输入、预期和实际结果。结果比较必须覆盖业务正确性。
- 修复依赖后重跑受影响样例；共享环境变更必须回归已有接入工具，不无故扩展检查。
- 候选 requirements 范围不等于完整锁；发布前在目标平台解析全部直接／间接依赖、记录精确版本与哈希，再执行样例验证。

## Security And Safety Rules

- 执行授权统一见 `AGENTS.md` 的 Approval Required；文档不能扩大授权。
- 业务 API 密钥留在 Mac Mini；报告、源码与 Drive 归档不包含原始密钥。
- 包索引凭据、带令牌的 URL、认证头及错误栈中的敏感值不得原样写出。
- 静态扫描不执行工具。样例试运行只有在输入、目标及外部副作用明确时开展。
- 真实写入失败后不得盲目重试；先确认实际结果与原工具的恢复语义。

## Contract Rules

- 报告遵守 `docs/CONTRACTS/intake-report.md`；枚举和必要字段由 JSON Schema 定义。
- `unverified` 是有效结果，不等于通过。报告中的扫描范围必须与实际检查一致。
- 接口变化同步更新契约与使用它的任务；当前报告是内部 v1，不承诺外部公共 API。

## Agent And Review Rules

- 不把前序助手建议升级为用户已经批准的架构决定；来源和状态见 DECISIONS。
- 只对实际缺口提问；用户已明确“不优先解决系统差异”，不得反复扩大该话题。
- 审查分别判断范围是否符合 SPEC、实现及证据是否符合契约。
- 未提供真实工具时报告“尚未真实验收”，不得编造工具、店铺、插件或运行结果。

## Admission Rules

- 所有 Skill／插件／模块上传后默认拒绝；自动验证完成并持久化白名单前不得出现在可调用目录。
- 静态报告、上传方提供的通过报告及 Agent 口头结论都不能直接写入白名单；验证器须自己观察实际云端执行与断言结果。
- 白名单按内容、环境、测试、连接上下文和入口绑定。版本名称相同而内容不同仍需重测；不能以一个入口通过开放插件所有能力。
- 调用器重新取得当前可信摘要，不信任用户传入的“已验证”字段；缺记录、状态未知、读取失败或上下文变化均拒绝。
- 被测工具与普通调用 Agent 无权写控制文件；若宿主不能限制该能力，记录强制机制未落实，不用提示词宣称替代。
- 自动验证用固定测试范围执行，既有授权内无需逐次人为审批；验证通过不授予额外账户、店铺或业务写入权限。
- 必须验证：上传未测拒绝、成功放行、失败与超时拒绝、修改后拒绝、名单损坏拒绝、撤销、重复回调不重复授予及执行快照与验证内容一致。
