# ARCH

Status: Active
Last Reviewed: 2026-10-12

## Product Shape

- Base profile: `custom`
- Capability modules: `identity-access, deterministic-workflow`
- Technology recipe: `none`
- Deviations: 权限模块仅覆盖验证器／调用器的职责与白名单写权限，复用宿主身份，不建设用户注册登录。工作流使用单云电脑的串行验证和受控文件记录，不引入数据库、调度平台或工作流引擎。

## Architecture Summary

工具上传 → 不可调用的待验证区 → 依赖核查 → 目标云电脑最小闭环 → 自动断言 → 受控白名单 → 逐次检查的业务调用入口。
外部环境是 Dots（运行）↔ Mac Mini（业务 API 代调），以及 Dots ↔ Drive（持久文件）。本项目核查这些连接是否满足某个工具，不实现它们。

## Implementation Status

- 已实现标准库静态盘点、纯准入判定，以及显式 local-demo 模式的快照／验证／名单／调用闭环。
- 本地执行适配器只运行可信合成 Python 脚本；无参数开启云端模式，云端入口默认返回 CLOUD_ADAPTER_UNAVAILABLE。
- 纯 Skill 加载、真实插件、宿主身份隔离及全调用旁路封闭尚未实现。当前受控文件权限只是本地演示约束，不能抵御同用户代码。
- 本地接口与证据格式见 `docs/CONTRACTS/local-demo.md`；使用方式见 README.md。

## Technology Stack

- 交付：Markdown Skill、Python 脚本、JSON 报告；首个脚本仅使用标准库。
- Python：采用标准 CPython 3.12 系列，初始构建候选为 3.12.15；目标环境联测后锁定构建与完整依赖。
- 公共运行时：一个受控环境；常用办公依赖与 OCR 按需扩展见 `docs/RUNTIME.md`，候选清单见 `runtime/requirements.in`。已定义基线，不代表云端已安装或验证。
- 文件：核查产物先写本地目录；Drive 归档使用已有能力，具体接入不在第一任务内。
- 无新增服务部署、包管理平台、数据库或付费服务。

## Module Boundaries

| Module | Responsibility | Owns | Must Not Own |
| --- | --- | --- | --- |
| 核查 Skill | 理解材料、补全依赖、引导验证与交接 | 核查步骤、证据解释 | 凭语言推测环境已通过、静默扩大业务授权 |
| 检查脚本 | 采集可重复验证的信息 | 输入校验、静态清单、结构化输出 | 自动安装、执行业务包、修改共享环境 |
| 试运行步骤 | 在明确输入和预期下调用已授权工具 | 命令记录、结果对照 | 绕过业务确认、无依据重试写入 |
| 自动验证与准入模块 | 执行云端最小闭环并维护有效白名单 | 测试记录、摘要绑定、通过／撤销记录 | 接受上传方自报通过、让被测工具写名单 |
| 统一调用入口 | 在调用前核对当前内容、环境、连接和入口 | 拒绝原因、执行已验证快照 | 先运行后检查、信任调用者提交的摘要、回退到直调 |
| 外部 Dots 环境 | 执行工具、提供已连接能力 | 运行环境与工作目录 | 在此项目内被重建或重新设计 |
| 外部 Mac Mini | 保存业务密钥、代调业务接口 | 密钥、实际接口权限 | 把业务密钥返回核查报告或工具包 |
| 外部 Drive | 保存需要持久化的文件 | 文件及既有访问权限 | 被默认为事务、锁或任务调度服务 |

## Data And Interfaces

- 本项目拥有检查报告、验证生命周期记录、白名单及证据引用，不拥有业务数据库。
- 报告接口：`docs/CONTRACTS/intake-report.md` 与 `docs/CONTRACTS/intake-report.schema.json`。
- 首个 CLI：`docs/CONTRACTS/static-inventory.md`。不提供公共网络 API。
- 准入接口：`docs/CONTRACTS/admission.md` 与 `docs/CONTRACTS/allowlist.schema.json`；状态机：`docs/CONTRACTS/workflow.md`；写入与调用职责：`docs/CONTRACTS/identity-access.md`。
- 网关、插件与 Drive 的真实接口依据首个工具补充，不虚构路径、请求字段、鉴权协议或账号身份。
- 每次报告记录来源与目标环境；结果文件放到独立输出位置，默认不覆盖已有文件。

## Considered Approaches

### 采用轻量 Skill 与确定性脚本

Skill 适合读出非结构化说明中的隐含条件，脚本适合复现检查。用户已选择这一首期范围；需要真实工具防止检查项脱离需求。

### 未选仅适配单个工具

范围更小，但不交付用户本轮明确要求的轻量复用能力。仍以单个真实工具限制首期验收范围。

### 暂缓通用发布与运行平台

当前瓶颈是依赖与可迁移性，发布平台增加基础设施，不能替代样例验证。

### 强制门槛由执行入口实施

Skill 负责编排验证与呈现白名单，受控验证器实际写入，调用器强制检查。仅在提示词写“不要调用未验证工具”无法满足此产品要求。未准入内容不能被宿主自动加载，已准入内容从不可变快照执行；平台若无法提供这一边界，首期强制保证尚不成立。

## Admission State Ownership

- 单一云端验证器串行处理：上传状态、执行日志和证据为持久文件，有效白名单为一个受控 JSON 文件；单写者、文件锁与原子替换防止半写状态。所有写入方必须遵守同一协议。
- 云端受控文件为调用时权威。Drive 保存归档，不作为正在运行的准入锁或可被运营编辑后立即生效的名单。这是对白名单控制数据的局部补充，业务文件仍按原方案持久化。
- 先持久化证据和名单，再向运营显示“可调用”。白名单写失败、文件损坏、云盘恢复或控制状态丢失时默认拒绝，重新验证后恢复，不从普通备份盲目信任通过状态。
- 白名单只存有效条目；失败／撤销历史保存在独立验证记录中。记录与名单跨文件不作为原子事务，采用先撤销后验证、证据先于授予的顺序，恢复时优先拒绝不一致记录。
- 没有多实例写入需求，不引入数据库。出现第二个写入实例时先更换具备事务语义的控制存储，再扩大部署。
- 业务调用入口与验证执行入口分开：前者只接受白名单，后者可运行待验证工具，但受固定测试输入、超时和授权范围约束，不能作为业务调用旁路。

## Dependency Rules

- 静态声明不等于依赖完整，安装成功不等于功能正确。
- 非 Python 依赖逐项记录具体能力，不以“装了某插件”代替可调用证明。
- 核查阶段不自动改动共享运行时；需要适配时先在临时副本验证，保留改变和回归证据。
- 不强制升降版本或换库来消除报错；OCR 准确性、文件版式和数值结果仍需对比。
- 工具内容、运行时、插件版本、测试用例／断言或连接授权上下文变化后，旧条目不得用于新条件。相关入口重新跑通后才放行。

## Operational Concerns

- 没有访问能力时标为未验证，环境不可达不自动转化为架构重建任务。
- 日志保留命令、退出状态和脱敏结果；不记录凭据、完整认证头或无关业务数据。
- 不把共享账号当作个人身份审计证据，不推断 buckets 已提供隔离。
- 核查报告与输入样本独立保存；文件归档失败应说明结果未持久化，不把业务操作重新执行。

## Open Questions

- 实际运行环境快照与首个样本缺失；无法给出已验证的包组合、插件探测命令或业务试运行命令。
- 真实工具出现后才确定试运行比较方法，例如表格字段、文档版式或 OCR 文本误差。
- 业务密钥留在 Mac Mini 的原则已确定；插件登录态及云端访问网关所需凭据的保存方式尚未设计，不得自行扩大“业务密钥不上云”的含义或声称已解决。
- 受控入口、待验证区和验证器身份在 Dots 上的实际实现方式未确认。共享 shell 若能直接运行待验证包或写名单，不能称为强制隔离；必须通过宿主执行策略或权限边界关闭旁路后验收。
