# SPEC

Status: Active
Last Reviewed: 2026-10-12

## Product Intent

让运营 A 上传的 Skill／插件／模块，在交给运营 B 使用共享 Dots 云电脑前，显式暴露运行所需条件，并强制在云端完成最小闭环验证。首期交付核查 Skill、配套脚本、自动验证与白名单准入模块，以一个真实工具完成端到端验收。

## Users

- A：工具作者，提供代码、附属文件、依赖声明、输入与预期输出。
- B：工具使用者，依据报告和说明独立使用，不依赖 A 临场补充。
- 协助核查的 Agent：阅读材料、运行确定性检查、解释缺口，保留证据。
- 用户／项目负责人：决定首个样本、业务预期和涉及外部写入的范围。

## Goals

- 找出工具依赖了哪些包、插件工具、网关接口、连接权限、配套文件和隐含操作条件。
- 对目标环境给出“已满足、缺失、冲突、未验证”，并指出证据与下一步。
- 有明确输入和预期结果的样例在目标环境通过，且 B 能按说明独立完成。
- 未通过云端验证的工具不能被业务调用；通过的具体版本和能力自动进入白名单。

## Non-Goals

- 自动上传、工具市场、自动发布、Web 管理后台及多租户调度。
- 本轮搭建 Mac Mini 网关、Google Drive 存储服务或 Dots 底层设施。
- 任意工具全自动迁移、任意插件重写、预装所有办公依赖。
- 把 macOS／Linux 差异作为专项；不支持本机 Mac 自动化迁移。
- 仅凭安装成功或静态分析宣称工具兼容。

## Core Workflows

1. 上传进入待验证区，不进入 Agent 的可调用目录；记录工具内容摘要、入口、依赖和测试用例。
2. Skill 补全依赖和测试说明，脚本执行确定性检查；缺少测试输入、预期结果或必要授权时，显示阻塞原因并保持禁用。
3. 自动验证器在目标云电脑内，从拟正式使用的入口执行最小闭环；不通过本地跑通、import 成功或全 mock 用例替代云端验证。
4. 验证输入经过核心操作并生成预期产物／响应，自动断言业务关键字段、数量或输出结构；保存执行和比较证据。
5. 仅验证器可将通过的“内容版本＋环境版本＋连接上下文＋已测入口”写入白名单；不要求运营逐次手动批准已经授权的无副作用测试。
6. 每次业务调用由统一入口重新核对名单和当前绑定；不存在、不匹配、被撤销或名单不可读时，在执行前拒绝。
7. 更新工具会产生待验证的新版本；旧版本仅在仍完整匹配原验证条件时可用。运营查看通过／失败原因；修复后重新验证，不能人工勾选跳过。

## Minimum Validation Loop

- 每个要开放的入口至少一例：明确输入 → 云端正式执行路径 → 真实核心依赖 → 可观察输出 → 自动结果断言。
- 纯 Skill 用目标 Agent 的实际加载与执行路径；插件逐个核查所暴露工具；模块用实际调用适配器。仅验证包内一个脚本不能代表整个插件。
- 验证绑定具体测试用例和断言，不能为了通过而临时把预期结果改成实际结果。
- 写入操作使用已授权测试资源并回读确认；只能验证预览时，只开放预览入口，不开放真实写入能力。
- 状态与恢复规则见 `docs/CONTRACTS/workflow.md`。待验证／验证中／失败／阻塞／撤销状态一律不可业务调用。

## Constraints

- 继承架构前提：Dots 承载运行，Mac Mini 保管业务 API 密钥并代调接口，Drive 承载持久文件，云端可保留运行日志。
- 用户希望维护一个公共环境，不引入多套长期虚拟环境；接入验证可用临时副本。
- 已定义云端公共运行时基线，详见 `docs/RUNTIME.md`；核心办公依赖受控安装，OCR 等扩展按实际需要加入同一环境。
- Python 和常见办公文件处理是主要对象；OOXML、PDF、OCR 与数据处理只按实际工具需要核查。
- 不要求运营手写 YAML；说明用 Markdown，结构化报告用 JSON。
- 控制首期规模，先解决依赖是否完整且可用，再考虑后续自动化。

## Acceptance Criteria

1. 对所检查材料说明覆盖范围；每个发现的依赖都有状态和证据，未知项不得被忽略。
2. 能区分包可用、插件能力可调用、账户／资源可访问与网关接口匹配。
3. 报告在未执行、受阻、失败时仍明确说明原因与下一步，不误报通过。
4. 一个真实工具在目标云端完成有预期结果的试运行；结果正确性单独核对。
5. B 按接入说明独立完成该工具的第二份输入，知道哪些成功、哪些失败。
6. 上传后的默认拒绝、云端验证后自动放行、内容／环境变化后重新拒绝、撤销以及名单故障拒绝均有可复查证据；无法拦截的旁路入口不能宣称实现了强制准入。

## Assumptions

- 为收敛范围，沿用云端基本执行与连接能力可行的设计前提；这不是本轮实测事实。
- 首期以一次一个工具的核查为单位，不建设并发任务系统。
- 一例通过只证明指定工具、版本、环境和输入范围，不保证任意输入。

## Implementation Status

2026-10-12 用户已授权实现并确认暂缺云端入口。静态盘点、准入判定与本地合成脚本闭环已实现；真实云端准入、Skill／插件宿主适配和真实工具验收仍未完成。不得把本地结果用于生产名单。

## Open Questions

- 用户于 2026-10-12 确认暂无首个真实工具；名称、来源、输入与预期输出均未提供。阻塞真实验收，不阻塞治理与静态盘点基础实现。
- 目标云端的可访问入口、环境实际版本及插件清单未提供。目标验证必须取得这些信息后再开展。
- 首个工具若涉及外部写入，须确定目标资源、可用测试方式及具体授权；当前没有业务写入授权。
- Dots 的 Skill 加载、插件暴露和模块执行能否全部经过受控入口，尚未核实。该问题阻塞强制准入的部署验收，不阻塞规则、契约和本地判定逻辑开发。
