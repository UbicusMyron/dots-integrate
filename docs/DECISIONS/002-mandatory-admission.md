# Decision: 强制云端最小闭环验证与白名单

Last Reviewed: 2026-10-12

## Status

用户于 2026-10-12 明确要求，已纳入首期治理；随后用户授权实现并接受先完成本地闭环；云端部署仍未开展。

## Context

用户要求运营上传 Skill／插件／模块后，必须强制在云电脑上完成最小闭环验证，通过后才能调用，并由 Skill 维护通过工具的白名单。该要求将先前“输出核查建议”扩展为“实际调用准入”。

## Decision

- 上传默认禁用。验证器自动执行固定用例并判定结果，通过后写受控白名单，调用器在每次业务执行前检查。
- 白名单粒度为工具不可变内容、环境、连接上下文、测试用例及具体入口；变化后重新验证。
- Skill 编排并展示列表，实际授予与拒绝由确定性代码和宿主权限边界执行。
- 当前已落地治理、契约、标准库实现和合成用例；本地记录明确标注 local-demo，不产生云端已通过工具条目。

## Reversibility

- Classification: 内部 v1 文件与任务可修订；调用资格含义不得静默改变。
- Human confirmation required: 强制准入原则已有用户明确授权，不重复询问。生产宿主身份／权限映射与部署仍按既有授权范围执行。

## Alternatives Considered

- 只有核查报告或提示词白名单：无法保证实际执行前被拒绝，不满足强制要求。
- 仅用工具名称：修改工具或环境后会沿用错误资格，因此采用内容与环境绑定。
- 首期引入数据库、任务平台或完整登录体系：没有当前需求，采用单写者受控文件和现有宿主身份。

## Consequences

真实样本缺失时没有工具可进入白名单，但可以开发静态盘点及纯判定逻辑。云端宿主若无法关闭直接执行旁路，强制准入的部署验收必须保持未通过；不能用文档已完成替代这一证据。
